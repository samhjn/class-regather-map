# 数据模型与导入

## 存储边界

`Classroom → Member → Location`；Member 在班级内拥有唯一 `student_code` 与可选 User，一个 User 可预留关联不同班级的成员资料。当前自助认领为每个新成员创建独立账号，尚未实现跨班账户合并。

`student_code` 保留为管理导入和重名登录的稳定标识，普通界面默认使用 `name`。`login` / `claim` API 接受 `name` 或 `student_code` 二选一；姓名无需唯一，重名登录拒绝自动选人并提示编号入口，重名认领使用一次性认领码匹配。姓名会随资料编辑 / 名单导入改变。展示顺序由前端在页面生命周期内随机排列，不依赖数据库默认排序。

所有业务路由为 `/c/{slug}/api/...`；客户端不能通过请求体自行指定班级或改写 user_id / is_admin。全站超级管理员可跨班访问，班级管理员严格限制在所属班级。审计记录包含班级、操作者、动作与目标 ID，不包含密码、认领码或位置完整副本。

Location 包含国家、行政区代码、地点名、可选点位、坐标系、实际起止日期、备注、更新时间与更新者。`confirmed_at` 记录本人最后一次确认这条位置属实的时间：只有本人新建、修改或调用 confirm 接口时才刷新，导入与管理员代改不会改动它；迁移时，本人改过的记录回填为 updated_at，其余回填为 started_on 当天 00:00。区间是左闭右开，同一成员不允许重叠；数据更新时同时使用数据库行锁与基于 updated_at 的乐观版本检查。

## 导入字段

CSV 使用 UTF-8（支持 BOM），英文表头。JSON 为相同字段的行对象数组。每次 1–1000 行，文件最多约 1 MB。

| 字段 | 含义 |
| --- | --- |
| student_code | 必填，班内唯一稳定编号，最多 64 字符；Excel 应按文本保存以保留前导零 |
| name | 必填，最多 60 字符 |
| bio | 可选，个人近况，最多 240 字符 |
| country_code | 有位置时必填，ISO 三字母代码：CHN/JPN/USA/SGP 等 |
| province_code | 中国位置必填，6 位省级行政区代码，如 330000 |
| city_code | 中国城市的 6 位市级行政区代码，如 330100；省直辖县级单位使用供应商返回的独立代码 |
| city_name | 城市名称，填写中国城市代码时必须填写；境外只填名称即可 |
| label | 地点说明，最多 120 字符；不要求详细住址 |
| longitude / latitude | 经度在前、纬度在后；成对填写或同时空；最多保留六位小数 |
| coordinate_system | gcj02 或 wgs84，内地有点位时必须为 gcj02 |
| started_on | 有位置时必填，YYYY-MM-DD，不可晚于今天 |
| ended_on | 可空；离开当日不再属于此地，必须晚于到达日 |
| note | 该段位置的近况，最多 500 字符 |

- 仅导入名单时只需 student_code 和 name。
- 同一个编号可多行表示多段历史，按到达日期升序填写，前段的 ended_on 与后段 started_on 衔接。
- 已有编号会更新姓名；只有提供 bio 字段才更新 bio。模板中的空 bio 会清空原有 bio。
- 有位置的行按 `(student_code, started_on)` 更新相同记录；更新行的空值会清空对应位置字段。不在文件中的位置不会被删除。
- 同一批次同一同学同一到达日期不可重复。补录新记录与数据库中的旧区间重叠时整批拒绝；如旧区间尚未结束，应先在文件中更新旧区间的结束日期，再列出新记录。
- 导入过程中会执行全部验证与数据库操作后回滚作为预览，确认时重新校验。预览签名绑定班级、管理员、完整导入内容且一小时过期；期间其他人编辑导致冲突仍会阻止提交。
- 同学认领状态、个人密码、权限、认领码不会由导入设置或覆盖。
- 港澳台归入 CHN 的 810000 / 820000 / 710000。直辖市及港澳自动归一化到对应省级代码作为城市；不会将区县误当成普通地级市。

## API 约定

读接口：`bootstrap`（解锁状态）、`snapshot?at=YYYY-MM-DD`（班级日期快照）、`members/{id}`（资料与完整足迹）。

写接口采用 JSON、同源 Cookie 会话及 `X-CSRFToken`。表单入口设置 CSRF Cookie，登录后 Cookie 旋转，前端每次请求重新读取。身份操作为 `unlock/login/logout/claim/password`；个人位置为 `members/{id}/locations` 和 `.../{location_id}`；管理员接口位于 `admin/`。

`POST members/{id}/locations/{location_id}/confirm` 传入 `version`，仅本人可调用（管理员也不能代为确认），只能确认当前有效的位置，只更新 confirmed_at，不改变 version。本人新建 / 修改位置或确认时可同时传 `bio` 与打开表单时的 `member_version`，个人备注与位置在同一事务内保存，备注版本不符返回 409 并整体回滚。

编辑个人资料传入旧 `updated_at` 作为 `version`；编辑或删除位置传入响应中的 `version`。版本冲突返回 409，不能静默覆盖。API 对非授权操作返回 403，不向公开页返回认领码哈希或他人登录编号。
